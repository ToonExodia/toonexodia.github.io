CTF - WEB

Puzzle involves needing to register as an editor by modifying the POST request when we log in, after which you make a publish a blog post with the admin as a collaborator. Reading the html, we can then see that we can accept the collaboration request on behalf of the admin. Doing so allows us to see the admins uuid, which allows us to see the admin password when we access /users/<uuid>. Logging in as admin, we see a ban user button, but after reading the provided code, its obvious that this is not the intended solve due to the blacklist of characters. After some further enumeration of the provided code, we see that we can access /data whcih allows us to download dbconnect.exe and secrets.zip. After that, all we need to do is the classic strings dbconnect.exe | grep pass which gives us a password that we can use to unzip secrets.zip and get the flag.

here is the zip file if you want to follow along Puzzle.zip

Enumeration

  • mention that we can make a post and add the admin as collaborator
  • mention that /db is public but is a dead end / red herring as the admin password there does not work
  • mention that in the post we can see the uuid of the person that posts it and the collaborator
  • in the collaborations pannel there is a script that allows us to accept a request on someone elses behalf but we dont have permissions
  • mention that we dont have permissions to view /user/<uuid>

privesc to editor

looking at the contents in auth.py we can see that when we register it makes us a user account by default, but if we intercept this request and change this value, its possible to register as an editor.

@app.route('/confirm-register', methods=['POST'])
def confirm_register():
    username = request.form['username']
    email = request.form.get('email', '')
    alphabet = string.ascii_letters + string.digits + '!@#$%^&*'
    password = ''.join(secrets.choice(alphabet) for _ in range(12))
    role = request.form.get('role', '2')

    role_map = {
        '1': 'editor',

    }

    if role == '0':
        return jsonify({'error': 'Admin registration is not allowed.'}), 403

privesc to admin

after registering as an editor we can now access /user/<uuid> with our own uuid and see the we can now access the page. So now the goal is to get the admins uuid. We do this by publishing a new article with the admin as a collaborator, accepting the collabortaion on the admins behalf, and then reading the html of the post to get the admins uuid and then log in as admin.

    async function acceptCollaboration(uuid) {
        try {
            const response = await fetch(`/collab/accept/${uuid}`, {
                method: 'POST'
            });
            if (response.ok) {
                window.location.reload();
            } else {
                const data = await response.json();
                alert(data.error || 'Failed to accept collaboration');
            }
        } catch (err) {
            alert('Error accepting collaboration');
        }
    }

running the acceptCollaboration(uuid) command in the console with the uuid of the post we want to accept, we can now see that the post is published on the home page.

now we can get the admin password by going to /users/<admin_uuid>.

after download the two files form /data all we now have to do is grep for strings, get the password, and unzip the file. after loggin in as admin, we can now access the /data page, and download dbconnect.exe and secrets.zip. after that all we now have to do is strings dbconnect.exe and grep for a password, unzip the secrets.zip file, and then cat the contents.
